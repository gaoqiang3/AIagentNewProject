# 对话微调学习计划（原理优先）

> 硬件：NVIDIA L40S 48GB（日常可用约 20GB）  
> 目标：对话（Chat）微调，手写脚本把原理吃透  
> 原则：先小模型手写训练循环，再 LoRA / QLoRA，最后上到能用的 7B

---

## 硬件怎么用

日常只剩约 20GB 时：

| 阶段 | 模型规模 | 方法 | 目的 |
|------|----------|------|------|
| 吃透原理 | 0.5B–1.5B | BF16 全参或 LoRA | 显存轻松，看清每一步 |
| 做出能用的对话模型 | 3B–7B | QLoRA（4bit） | 效果与成本平衡 |
| 整卡空闲（~48GB） | 7B/14B | LoRA BF16 | 拉高质量 |

推荐底座进阶路径（同一套 chat template，方便升级）：

1. `Qwen2.5-0.5B-Instruct`
2. `Qwen2.5-1.5B-Instruct`
3. `Qwen2.5-7B-Instruct`

## 原理学习顺序

### 第 0 周：先会推理

手写脚本：加载模型 → `apply_chat_template` → `generate`。

必须搞懂：

- tokenizer
- special tokens
- chat template
- left / right padding

**不过这关，后面训练必翻车。**

验收：能对同一模型用官方模板稳定多轮对话。

---

### 第 1 周：手写最小 SFT（核心）

自己写训练循环，不要一上来 Trainer 黑盒。

步骤：

1. 数据：`messages = [{role, content}, ...]`
2. 拼成模型输入，并做 **labels mask**（只对 assistant 段落算 loss）
3. `model(**batch).loss` → `backward` → `optimizer.step`
4. 看 loss 下降，再对比微调前后同一问题的回答

必须能回答：

- 为什么 user / system 部分的 label 要设成 `-100`？
- 训练时 next-token prediction 与 `labels` 的关系是什么？（HF 内部已处理移位，但原理要懂）
- 多轮对话里，哪些 token 该学、哪些不该学？

验收：手写脚本跑通；loss 下降；微调前后回答可对比。

---

### 第 2 周：LoRA（参数高效）

同一套数据，把全参改成 LoRA：

- 只往 `q_proj` / `v_proj`（或再加 `k` / `o` / `gate` / `up` / `down`）插适配器
- 对比：可训练参数量、显存、效果
- 搞懂：`r`、`alpha`、`dropout`、合并权重 vs 只分发 adapter

验收：能说清「为什么 LoRA 省显存、省存储，却仍能改行为」。

---

### 第 3 周：QLoRA + 正规训练

用 `peft` + `trl.SFTTrainer` 复现一遍手写过的流程：

- 4bit 量化底座 + LoRA
- gradient checkpointing、packing、cosine LR
- 保存：adapter / merge 成完整模型
- 升到 `Qwen2.5-7B-Instruct`（约 20GB 可用场景的主战配置）

验收：7B QLoRA 能稳定训完一个小 epoch，并导出可推理权重。

---

### 第 4 周：评测与对齐入门

- 固定 20–50 条人工题，做微调前后对比
- 学习 **DPO**（偏好对：chosen / rejected）
- 理解：对话「产品味」往往靠偏好对齐，不只靠 SFT

验收：有一份简单评测集 + 前后对比记录；能口述 SFT 与 DPO 的区别。

---

## 数据（对话微调真正的门槛）

先自己做 **100–300 条** 高质量多轮，格式：

```json
{
  "messages": [
    {"role": "system", "content": "你是简洁、专业的助手"},
    {"role": "user", "content": "……"},
    {"role": "assistant", "content": "……"}
  ]
}
```

原则：

- 风格统一，比堆 1 万条脏数据重要
- 微调适合：**口吻、格式、任务套路**
- 不适合：硬背最新事实（用 RAG；本仓库已有嵌入 / LangGraph 基础可衔接）

## 两周验收标准（阶段检查）

能自己讲清楚并演示：

1. chat template 不一致会导致什么现象
2. 为什么只训 assistant
3. LoRA 为什么省显存
4. 同一道题，微调前 / 后回答差在哪
5. 20GB 下 7B QLoRA 的大致 batch / seqlen 配置

---

## 学习原则（避坑）

- 先小模型手写，再框架封装；先 SFT，再 DPO
- 训练与推理必须使用**同一套** chat template
- 学习率过大容易把底座能力训崩
- 数据少又脏 → 模型会学坏说话方式
- 日常 ~20GB：优先 QLoRA；不要一上来全参硬训 7B+
